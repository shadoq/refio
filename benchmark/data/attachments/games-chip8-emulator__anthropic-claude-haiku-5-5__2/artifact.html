    About / Notes

    The emulator core (Chip8Core) is separate from the UI. The core implements the 34 base CHIP-8 opcodes with exact-pattern decoding, the default compatibility settings above, validated memory bounds, stack fault checks, FX0A fresh-keydown waiting, and a 200-entry trace. Legacy SYS 0NNN is decoded and reported as unsupported; it is not emulated.

    Verification status: The code was written without being executed in a browser in this session. The built-in self-tests exercise the core in isolated instances and report expected vs observed results; run them to check behavior in your browser. Treat any test that fails as a real finding.

    Built-in demo: loads at 0x200 (76 bytes), starts paused. Press any key to start (FX0A). Move the sprite with the keypad keys 2 (up), 8 (down), 4 (left), 6 (right), which are physical 2, S, Q and E on the keypad labels. Hold key 0 (physical X) to beep via ST. Movement is paced by the delay timer. The sprite is drawn by a CALL/RET subroutine at 0x240 and wraps/clips at the screen edges. All behavior comes from CHIP-8 instructions; the JavaScript only loads bytes and renders state.

    Notes:

    • Fault conditions (unknown or invalid opcode, invalid fetch, out-of-bounds memory access, stack overflow/underflow, unsupported SYS) pause execution, silence audio, and keep the faulting PC, opcode and explanation.
    • Editing registers or PC clears a fault so you can continue from modified state; Reset always restores the loaded ROM and a clean machine.
    • Keypad labels are authoritative: the 1 2 3 C row uses physical 1 2 3 4, so keypad key 2 is physical 2.
