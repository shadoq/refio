KeyVault's login state machine in server/app.py kept LOGIN_STATE keyed by username, one entry per user holding the current session token and a verified flag, and POST /login carried the existing verified flag forward when it minted a new token. Once a user had completed 2FA once, a second login with only the password inherited verified = True and could read GET /vault directly, so the second factor was never re-requested (a session reset/fixation flaw).

The fix re-keys LOGIN_STATE by session token, one entry per login with its own user and verified fields: POST /login always creates a new pending (verified = False) entry and deletes every previous entry of the same user, so each fresh login requires POST /verify again and the stale session is refused with 401, while the happy path (login, verify, vault) and per-user isolation keep working. python3 tests/test_2fa.py passes all 14 checks; report/fix.md records state_key_before = username, state_key_after = session token and sessions_invalidated = yes.
