# INC-2141: job worker dies every few minutes after the 3.2.0 deploy

## Summary

Since the 3.2.0 deploy went out last night the catalog job worker behind the
order dashboard is restarted by the supervisor every 2 to 5 minutes. The
process always exits with code 1. Customers see stale job data until the
supervisor restarts the worker.

## Timeline (all times UTC, from logs/app.log)

- 02:00 worker 3.2.0 starts, first rounds succeed
- 02:12 first crash, "uncaught exception", exit code 1
- 02:12 to 02:27 the pattern repeats five times: a few minutes of "refresh ok"
  lines, then a crash, then a supervisor restart

## What we know

- The deploy only touched the refresh and retry code under `src/`.
- Node 20 runs with the default `--unhandled-rejections=throw`, so an unhandled
  rejection terminates the process with exit code 1.
- The last log line before every crash is "refresh ok", which makes no sense
  given the crash that follows immediately after.
- The crash trace does not say which job was being refreshed.

## Ask

Find the defect chain, fix it at the root cause in `src/`, and make sure a
failing catalog item is reported instead of taking the worker down.
